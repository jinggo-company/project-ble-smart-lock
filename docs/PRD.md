## 需求概述：雇主有一款 BLE 智能锁，外包 App 团队正在开发新版本 App，但缺乏固件工程师。需要熟悉 BLE/嵌入式的工程师协助完成 App 与固件的通信对接，修复 3 个现有固件 Bug，并实现低电关机新功能。

**立项理由**：需求真实明确，已有 App 团队协同，只需固件端支持。技术可行性高（BLE 固件调试属于常规嵌入式开发），预算虽偏低但可作为标杆案例获取更多类似 BLE/IoT 固件开发项目。

## 技术栈

- **硬件平台**: nRF52832/52840 SoC（Nordic Semiconductor）
- **RTOS**: FreeRTOS + Nordic SoftDevice（BLE 协议栈）
- **BLE 协议**: BLE 5.0，AES-128-CCM 加密通信，LESC 配对
- **GATT 服务**: 自定义锁控服务（开锁/上锁/状态查询/电量查询）
- **电机驱动**: GPIO 控制 + Hall 传感器锁舌检测
- **OTA**: Nordic DFU（Device Firmware Update）
- **开发工具**: nRF Connect SDK、SEGGER J-Link、逻辑分析仪

### 关键决策
1. **加密方案**：采用 BLE LESC 配对 + AES-128 会话加密，确保开锁指令传输安全
2. **状态机设计**：采用显式状态机（空闲/配对中/已连接/开锁/上锁/低电关机），避免隐式状态导致的偶发卡死
3. **日志存储**：Flash 环形缓冲存储开锁日志，掉电不丢失，支持离线审计

## 验收标准（Acceptance Criteria）

### AC-1：Bug 修复 — 杆插入无响应
- Bug 1 在连续插入 100 次后，锁响应率 ≥ 99.9%（原 10% 可复现）
- 提供复现步骤和修复说明，App 团队可独立验证

### AC-2：Bug 修复 — 解锁状态超时后上锁
- Bug 2 在解锁状态超时后，上锁功能 100% 正常执行
- 状态转换日志可追溯，无残留中间状态

### AC-3：Bug 修复 — 上锁状态解锁后状态残留
- Bug 3 修复后，解锁→超时→拔杆后，状态正确回到"未锁定"
- 状态同步延迟 ≤ 500ms

### AC-4：低电关机功能
- 电压 ≤ 3.0V 时，设备在 3 秒内停止所有非关键操作
- 蜂鸣器发出低电提示音（频率 1Hz，持续 3 秒）
- 低电状态下拒绝所有开锁/上锁指令，返回错误码

### AC-5：App 对接 — BLE 连接
- App 发起 BLE 连接后，5 秒内完成 GATT 服务发现
- 断开后 10 秒内自动重连（3 次重试）
- 支持 3 个设备同时连接，第 4 个被拒绝

### AC-6：App 对接 — 数据通信
- 开锁指令加密传输，AES-128 解密成功率 100%
- 未加密/篡改消息被锁控板拒绝，返回错误码
- 通知订阅机制正常，状态变更 1 秒内推送至 App

### AC-7：交付文档完整性
- 对接文档包含：GATT 服务定义、特征值列表、读写格式、重试策略
- 固件版本包含：源码/patch、编译说明、版本说明、变更日志
- 测试报告包含：每个 Bug 的复现步骤、修复验证、回归测试结果

### AC-8：性能与稳定性
- 锁控状态机响应时间 ≤ 200ms（从指令接收到执行完成）
- BLE 通信丢包率 ≤ 0.1%（距离 3 米内）
- 连续运行 72 小时无崩溃/死机
